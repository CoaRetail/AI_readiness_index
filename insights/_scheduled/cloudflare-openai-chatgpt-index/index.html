Agent Readiness/ Insights/ ChatGPT索引

2026.10.31 Column

article

CloudflareとOpenAIは2026年7月から研究パイロットで、参加サイト約1%から、OpenAIの検索索引に数億ページを追加したと10月15日に書きました。信号は発見の補助で、順位はOpenAIが独立に決めます。引用や流入は保証されません。

Cloudflareの信号は、ChatGPT検索の索引に何を足したか？

以前は索引に載っていなかったページが、OpenAIの検索索引に入った、とCloudflareは2026年10月15日に書いています。2026年7月に始めたOpenAIとの研究パイロットの初期結果です。参加コホートはCloudflareネットワークの約1%で、数億ページ規模の新規索引、と書いています。ページが見つかっても、ChatGPTの回答に引用される保証は、この投稿にはありません。送客量やクリックも報告していません。

信号は、順位や引用を決めるか？

決めない、と書いています。Cloudflareのネットワーク信号は、OpenAIの検索クローラーが有用なページを見つける助けになる、と説明しています。その後の評価と順位付けは、OpenAIが関連性と有用性に基づき独立に行う、と同じ投稿は書いています。信号があるからアクセス許可が付くわけでもありません。メタデータは検索と発見向けで、モデル学習用の本文共有ではない、とも書いています。

どんな信号が試されているか？

存在しないURLやリダイレクト先への無駄な取得を減らすフィルタ、ページが再訪に値するかどうかの変更信号、侵害された可能性のあるページを示す信号（テスト中）、が2026年10月15日の投稿にあります。2026年7月8日のプレスリリースは、コンテンツの新しさ、トラフィックの質、実際のページ変更といったリアルタイムのネットワーク洞察にも言及しています。参加サイトの範囲と、新規ページがどのホストにあったかは、どちらも公開していません。

サイト側で何が変わるか？

新しいページを見つける段階では、評価と索引のためにクロールが一時的に増えることがある、と10月15日の投稿は書いています。変更のないページを何度も取りに来ないようにするのが、変更信号の目的です。Cloudflare顧客にとっては不要な負荷を減らす、OpenAIにとっては検索リソースを有用な情報に向ける、という意図です。AI Crawl ControlでAIアクセスを管理できる、とも書いています。robots.txtのOAI-SearchBotとGPTBotの扱いは、この記事では詳述しません。<a href="/insights/files/">robots.txt・sitemap・llms.txtの違い</a>は別の記事です。

ビジネス成果は、保証されているか？

保証されていません。次の段階は、ページ選定の改善、変更信号の高速化、発見後の測定、と10月15日の投稿は書いています。発見改善が売上やリードに結びつくかは、継続検証中です。索引に載ったからといって、自社ページが回答に出るわけではありません。順位もCloudflareの信号そのものではありません。
