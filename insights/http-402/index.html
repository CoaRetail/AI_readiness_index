HTTP 402とx402｜AI決済が示すAgent Commerce

HTTP 402は「支払いが必要」を示すステータスコードで、x402はAIエージェントが決済まで自律完結する方向の仕組みです。予約の次の関門は決済であり、Agent Commerce時代にはActionabilityの一部として求められます。

生成AIが急速に普及したことで、多くの企業は「AIに見つけてもらうにはどうすればいいのか」という課題に向き合い始めています。

しかし、その変化はまだ序章に過ぎません。

これから本当に変わるのは、「AIが検索すること」ではなく、「AIが行動すること」です。

企業を探し、比較し、予約し、そして支払いまで完了させる。

そんな世界を実現するための技術として、今「HTTP 402（Payment Required）」と「x402」というキーワードが注目されています。

長年使われなかったHTTP 402が、なぜ今注目されるのか

HTTPには、Webサービス同士がやり取りをするための共通ルールがあります。

例えば、

  • 200 OK（正常終了）
  • 404 Not Found（ページが見つからない）
  • 401 Unauthorized（認証が必要）

などは、多くの人が一度は目にしたことがあるでしょう。

その中に、実は昔から「402 Payment Required（支払いが必要）」というステータスコードが存在していました。

しかし、このコードは長年ほとんど利用されることがありませんでした。

理由はシンプルです。これまでインターネット上の決済は、人間がクレジットカード情報を入力し、決済画面を操作することが前提だったからです。HTTPレベルで「支払い」を扱う必要性があまりありませんでした。

ところが、AIエージェントの登場によって状況は大きく変わります。

AIがAPIを利用し、データを取得し、サービスを実行する世界では、人間を介さずに利用料金を支払う仕組みが必要になります。

その入口として再び注目され始めたのが、HTTP 402なのです。

HTTP 402は「決済機能」ではなく、「支払いを要求する共通言語」

ここで誤解してはいけないのは、HTTP 402自体に決済機能があるわけではありません。

HTTP 402は、

このサービスを利用するには、先に支払いが必要です

ということをAIやアプリケーションへ伝えるための共通ルールです。

例えばAIがあるAPIへアクセスすると、

このAPIを利用するには0.01ドル相当を支払ってください

という情報がHTTP 402として返されます。

AIはその内容を理解し、対応する決済手段で支払いを済ませたあと、再びAPIへアクセスします。

支払いが確認されると、今度は通常どおりデータが返されます。

つまりHTTP 402は、決済そのものではなく、「決済フローの入口」を標準化する仕組みなのです。

x402が目指しているもの

最近では、このHTTP 402を実際に運用するためのオープン仕様として「x402」が登場しています。

x402は、AIエージェントが機械同士で料金を支払い、サービスを利用できるように設計された仕組みです。

現在はXRP Ledger（XRPL）やRLUSDなど、ブロックチェーンを活用した実装が進んでいます。これは、AIが24時間365日、自律的に少額決済を繰り返す用途と非常に相性が良いためです。

ただし、本質は「ブロックチェーンだからすごい」という話ではありません。

重要なのは、

AIが人間の代わりに取引を完了できること。

ここにあります。

将来的には、Stripeのような既存決済サービスや銀行決済なども含め、多様な決済手段と連携する可能性があります。

HTTP 402は、そのどれか一つに依存するものではなく、「AIへ支払い条件を伝える共通インターフェース」と考える方が分かりやすいでしょう。

予約はできても、決済できなければAIは最後まで動けない

私はこれまで「Agent Readiness」という考え方を提唱してきました。

AIが企業を見つけ、理解し、比較し、推薦する。ここまでは、多くの企業が関心を持ち始めています。

しかし、その先があります。

AIが予約し、AIが決済し、AIがサービスを実行する。

ここまで実現できて初めて、「AIが行動できる企業」と言えるのではないでしょうか。

私はこの状態を、Agent Readinessの中でも特に重要な要素である「ACTIONABILITY」と位置付けています。

これから企業が準備すべきこと

今後、x402が世界標準になるかどうかはまだ分かりません。新しい仕様が登場する可能性もありますし、既存の決済インフラが進化する可能性もあります。

しかし、方向性は明確です。AIは「情報を読む存在」から、「実際に行動する存在」へ変わり始めています。

そのとき企業に求められるのは、

  • AIが企業情報を理解できること
  • AIがサービス内容を比較できること
  • AIが予約できること
  • AIが決済できること
  • AIが最後まで取引を完了できること

です。

つまり、ホームページを持っているだけでは十分ではありません。

AIが企業を理解し、判断し、そして取引まで実行できる状態を整えること。それが、これからの競争力になります。

AIに「選ばれる」から、AIと「取引できる」企業へ

SEOは、人に見つけてもらうための時代の最適化でした。

GEOは、生成AIに引用・参照されるための最適化です。

そして、その先にあるのがAgent Readinessです。

AIが企業を理解し、比較し、推薦し、予約し、決済し、実行する。

これから企業が目指すべき姿は、「AIに選ばれる企業」だけではありません。
AIと直接取引できる企業になること。

HTTP 402やx402は、その未来を支える技術の一つとして、今後ますます注目されていくでしょう。
